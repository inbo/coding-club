Check examples in the [DBI homepage](https://dbi.r-dbi.org/#example). --- class: left, top # Intermezzo 1 - database schemas The function `dbListFields()` worked well. So, why not trying the DBI function `dbListTables()` to get all the names of all the tables? Just try: ``` dbListTables(florabank) ``` 789 tables??? And all that strange names? Well, that's because the `florabank` database is a SQL Server database and the DBI function `dbListTables()` is not able to filter on the default schema `dbo`. So, you get all tables in all schemas and much, much more. But wait a minute: what's a *schema*? and why do we have multiple schemas in a database? A schema is a way to *logically group* database objects like tables within a database. It helps organize and manage the database structure, especially in larger databases with many objects. In SQL Server, the **default** schema is **`dbo`**, but other schemas can be created for different purposes or users (check e.g. the INBOVEG database `D0010_00_Cydonia`). And there are also *system schemas*, like *`sys`*, which contain system tables that are used by SQL Server for internal management and operations. System schemas are NOT for user data, but for advanced database management and troubleshooting = never, I say, never touch them unless you are Frederic, Geert, Jo or some very few else from the data management team!* * Typically and luckily we don't even have the rights to touch sys schema. But it's good to know what they are and why we should never touch them :-) Do you really want to get table names from dbo schema? Filter on the `dbo` schema using the following code, where we use the function `dbGetQuery()` to run a SQL query on the database connection `florabank`: ```r library(DBI) dbGetQuery(florabank, " SELECT s.name AS schema_name, t.name AS table_name FROM sys.tables t JOIN sys.schemas s ON t.schema_id = s.schema_id WHERE s.name = 'dbo' ") ``` --- class: left, top # Intermezzo 1 - database views What else can you find in a schema? Well, besides tables, there are also *views*. A view is a *virtual table*, call it a *saved search* or a *saved recipe* that is based on the result of a SQL query. It looks and acts like a table (you can query it, filter it, join it), but it doesn't store any data of its own.-! It's just a stored instruction: _"go fetch this specific slice/combination of the real tables, and show it to me as if it were one table."_ How to recognize them? - In RStudio, you cannot open a view of a view 😄 No "table" symbol 𝄜 next to its name in connection pane - Their names typically start with `vw`. Example: the `inbo` schema of INBOVEG database `D0010_00_Cydonia` has no tables, only views. .center[![:scale 100%]({{ site.baseurl}}/assets/images/20260929/20260929_views.png)] --- background-image: url({{ site.baseurl}}/assets/images/background_challenge_2.png) class: left, top # Challenge 2 - --- class: left, top # Intermezzo 1: R is lazy... so are we Let us get the locations from watina database using watina function `get_locs(watina)`. Why do you get an error if you try to save them in a text format (e.g. csv)? ```r locations <- get_locs(watina) write_csv(x = locations, file = "./data/locations.csv") > Error in write_delim(x, file, delim = ",", na = na, append = append, col_names = col_names, : is.data.frame(x) is not TRUE ``` Is locations not a data.frame??? ```r class(locations) [1] "tbl_Microsoft SQL Server" "tbl_dbi" [3] "tbl_sql" "tbl_lazy" [5] "tbl" ``` All you have is a table (`tbl`), but most of all, it's a _lazy table_... Welcome to the lazy woRld! --- class: left, top # Intermezzo 1: R is lazy... so are we ![:scale 100%]({{ site.baseurl}}/assets/images/20220125/20220125_lazy_query.png) `locations` is an SQL query, no data are really loaded on your laptop. It is like a reference to the result of the query but the full result of the query is not brought into memory. If you are thinking: _"are you kidding me?"_ Well, try this: ```r locations %>% show_query() ``` IMPORTANT: to avoid bad surprises (crashes, out of memory issues), first run your queries lazily. --- class: left, top # Intermezzo 2 - R is lazy... ![:scale 10%]({{ site.baseurl}}/assets/images/20220125/20220125_mister_lazy.jpg) R is not only lazy with databases, R is ALWAYS lazy ```r number <- 5 multiply_by_2 <- function(a, b) { a * 2 # b is not used } multiply_by_2(number) # no value given to argument b ``` `b` is a function argument, but never evaluated, so no error. This is what we mean by being **lazy**: doing **the strict minimum** of evaluation*. For this reason lazy evaluation is sometimes referred as _call-by-need_. *More about lazy evaluation? Give a look at [this tutorial](https://www.r-bloggers.com/2018/07/about-lazy-evaluation/)... or spend a coffeebreak with Thierry ;-) --- background-image: url({{ site.baseurl}}/assets/images/background_challenge_3.png) class: left, top # Challenge 3 - Templates https://tutorials.inbo.be/tutorials/r_database_access/#create-and-use-query-templates --- class: left, top # Contribute to inbodb We have just learned that R is lazy.
